# ADR-0006: Entity-Component-System design

- **Status:** Accepted
- **Date:** 2026-10-27

## Context

The ECS is a core engine system and a learning objective (OVERVIEW §8). It needs a defined handle validity model, hierarchy, and transform propagation.

## Decision

- A custom sparse-set ECS: one pool per component type, dense arrays for iteration, swap-and-pop removal.
- `Entity` is an index plus a generation counter. Destroying an entity increments the generation, so stale handles are detected.
- Systems are run by an explicit, ordered schedule. No automatic dependency solving.
- Hierarchy: the `World` keeps parent, first and last child, and sibling links for entities that have relations. The links are not a public component, so they cannot be edited into an inconsistent state. Reparenting rejects cycles. Destroying a parent destroys its children.
- `LocalTransform` is authoritative; `WorldTransform` is derived by a top-down propagation that recomputes every world transform on every call (amended 2026-10-28, see below).
- Only engine components live in the engine (transforms, hierarchy, camera, mesh renderer, light, physics, audio). Game components (health, movement, AI controller) belong to game or sample code.

## Consequences

- The ECS has no dependency on rendering or platform code and is fully unit-testable.
- If the custom ECS becomes a maintenance burden, EnTT has a close design and can replace it.

## Alternatives considered

- EnTT: mature and fast, but the project wants to understand the ECS fully, and hierarchy would still need to be written.
- Archetype-based ECS: faster iteration for large worlds, more complex; not needed for indoor scenes.

## Amendment (2026-10-28): no dirty flags

Components are edited through plain references (`world.Get<LocalTransform>(e).translation = ...`), so
nothing records that a transform changed unless the caller remembers to mark it, and a forgotten mark
leaves a stale world transform (OVERVIEW §8.5). Propagation therefore recomputes every world transform
on each call. The cost is one matrix product per entity, which is small for indoor scenes. Dirty
flags, behind setter functions so that they cannot be forgotten, will be added only if the profiler
shows propagation to be a problem.
